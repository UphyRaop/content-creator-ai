# Phase 8 Rendering Engine QA Plan

**Task:** P8-QA-PLAN-01 (CCAI-05-QA)  
**Status:** Test matrix drafted; initial implementation fixture passed but independent review found three blocking timeline/approval defects. Corrected implementation and second review are pending.  
**Scope:** Real local FFmpeg rendering on the Node.js host, plus the static GitHub Pages simulation boundary. Keep all AI/media generation simulated and free; do not enable paid providers.

## Test setup and evidence

Use a small, deterministic fixture project containing approved still images, approved audio clips, estimated captions, at least one transition, and motion. Include portrait and landscape cases, one no-caption case, a caption-heavy case, and malformed or unsupported inputs. Generate only test media locally. Record app commit, Node and FFmpeg versions, command arguments or normalized manifest, exit status, output size, `ffprobe` stream metadata, and test logs with secrets redacted. Delete generated media after checks unless an artifact is specifically needed for review.

`ffmpeg 7.1.5` with x264/AAC, zoompan, xfade, subtitles, and amix is available in the current local environment. Treat that as local-only capability; GitHub Pages is static and cannot run FFmpeg or the SQLite API. This plan states acceptance targets, not results.

## Execution boundary

**Run-ready headless checks:** schema validation, manifest normalization, argument construction inspection, injection cases, path containment, output naming/collision policy, progress parsing, job state transitions, cleanup decisions, retry identity, and secret scanning. Mock child-process failures and filesystem errors for deterministic cases.

**Local-only integration checks:** actual FFmpeg spawn, MP4 render/probe/decode, codec/dimension/FPS/audio/caption checks, cancellation, retry, temp/output cleanup, and rendered transition/motion fidelity. Require the Node.js host with FFmpeg installed and write access to its configured media directories. GitHub Pages cannot run these checks.

**Browser/manual checks:** render progress/cancel/retry controls, output messaging/download behavior, playback in target browsers, caption readability, and comparison of the actual render to the simulated editor preview. Use desktop plus iPhone-sized viewport/device. Do not mark mobile or media playback accepted from headless tests alone.

## Assumptions and blockers

- FFmpeg uses a local installed executable; no hosted rendering service or paid provider is part of Phase 8 acceptance.
- Approval gates remain mandatory, all generated inputs are approved project assets, and render consumes a validated Phase 7 manifest. Render itself does not mutate source images/audio or their approval history.
- Document exact resolution, FPS, codecs/profile, pixel format, audio layout, caption mode, duration tolerance, output retention, temp storage, and concurrency limits before turning metadata expectations into fixed assertions.
- FFmpeg availability and version vary by host. Record feature/version checks and fail closed with a clear message if required filters/codecs are absent. The current local 7.1.5 installation does not establish target-host availability.
- Initial local evidence before fixes: `node --experimental-strip-types scripts/test-ffmpeg-renderer.mjs`, `npm test`, `npx tsc --noEmit`, `npm run build:static`, `npm run build`, and `git diff --check` passed. The fixture proved one landscape, 30 FPS cut-transition MP4 with video/audio and captions.
- The first independent CCAI-05-QA review failed the implementation because the server path did not fully require approved voice, discarded absolute image clip starts/gaps, and rejected the editor's crossfade transition. Browser interaction, portrait/60 FPS, progress/cancel/retry, metadata codecs/FPS, transition fidelity, failure cleanup and injection cases were not verified by that initial run.
- Corrected Phase 8 code and a follow-up QA review are still required. GitHub Pages cannot execute the Node/FFmpeg server routes, and no Node production host is configured. Do not mark the server renderer as deployed or available on the live Pages preview.
